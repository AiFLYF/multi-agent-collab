## 上一轮会话活动、待机与完成提示词（2026-11-09）

原本依赖专门 heartbeat 判断活动，会把持续使用其它命令的会话误判为失活；只写“完成后 finish”的提示也缺少真正的执行触发点。
本轮把最近活动、任务状态与文件占用分开，给普通调用增加活动更新，并把最终答复前的真实收尾集中到启动清单。

| 使用情形 | 该轮机制 |
|---|---|
| 正常套件命令带本人平台与会话 ID | 核验记录、工作区和实际分支后节流更新 heartbeat/last_activity，不改任务、范围或阅读回执 |
| 旁观看板、匿名查询或纯审计 | 不推断自己是哪个会话；网页轮询不续活，--no-activity、预览与更新检查保持零写 |
| 测试、构建或其它原生命令 | 用 run 明确归属，原样传递参数/输出/退出码，登记 wrapper 和 child PID，不存完整参数 |
| 当前任务完成，继续等要求 | finish --standby 保存原任务、范围和实际结果，释放 files=[]，保留 ID |
| 待机接到新任务 | activate 重新给 task/完整 files 并核验当前分支、策略、占用和人类指令 |
| 未完成或受阻 | handoff 保留占用；待机不能用 resume/heartbeat 偷加范围，done 不可复活 |
| 命令未结束或进程状态未知 | 收尾和范围转换被拦截；同任务并行命令各清理自己的记录，全部结束后才释放 |
| 执行期间收到普通补充说明 | 只提示，按内容版本去重，保留当前授权命令结果；下一条命令前仍核验新要求，显式控制持续拦截 |

三个子代理分别审查活动、待机和提示词，主会话统一登记并整合。13 个平台入口指向开工、执行中与答复前清单，

## 统一消息提示与新一轮验证（2026-11-08）

新增消息机制由各业务命令顺带返回极简提示，正文仍按需读取。来源覆盖人类指令、AI 留言、交接和已答回复；

## Token 成本

使用 [`measure_context.py`](../scripts/measure_context.py) 可离线复核字符和 UTF-8 字节；精确编码计数需要已有的可选 `tiktoken` 缓存。

| 2026-11-08 RULES + START_HERE 实测 | 基线 2e8ba9e | 当前 | 减少 |
|---|---:|---:|---:|
| 字符 | 12,203 | 5,432 | 55.49% |
| UTF-8 字节 | 21,744 | 11,178 | 48.59% |

当前编码缓存缺失，脚本返回 `tokens=null`，**6,500 字符**静态预算通过，不自动安装依赖或下载编码数据。
6,351→2,837 tokens 是 2026-11-04 的编码快照；12,203→5,075 字符与 21,744→10,455 字节是消息机制加入前的 2026-11-07 历史值。
它们不代表本轮当前文本或模型账单。

初轮 102 条真实命令和 30 组输出采样显示，无消息时 context/brief/心跳输出长度与同机旧套件一致；
2940 字符 AI 消息首次提示为 634 字符，按需 read 一次为 4007 字符，随后心跳回到 109 个 LF 归一字符。
按该采样口径构造 10 轮输出：39,750→5,622 字符，减少 85.86%；这是实测长度的场景算术。
最终安装后补测的已读 AI 心跳为 109 个 LF 字符（Windows 原始 115 字节），已读 open 人类事项为 254 个 LF 字符（原始 267 字节），
默认 read 为空且不写记录，通知的 read_command 为 null。源路径和换行口径影响长度，不由顺序耗时样本推断提速。

```text
python scripts/measure_context.py --baseline 2e8ba9e --check --json
python tools/agents_status.py --context --agent codex --max-chars 6000
```

动态预算是字符上限，包含最后换行，不冒充精确 token 数。截断会列出未读数量、路径和完整展开参数，返回 1；先读取原文再处理，不能据此跳过暂停指令或直接确认完成。
已结束记录不进入摘要，closed inbox 正文不为摘要重复读取，日志只选择近期文件；每次动态检查重新采集，没有长期状态缓存。

进一步控制成本应靠任务边界：子代理拿到具体目标、文件范围、输入和验收条件，复用父会话的必要上下文，交付结果与证据。
共享工作区中的同任务子代理由一个父会话登记，不能各自切分支和抢占整个工作区。模型 API 的实际用量需要调用方提供，这个套件不伪造账单或自动调用模型。
