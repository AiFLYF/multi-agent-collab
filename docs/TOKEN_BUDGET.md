# Token 预算与上下文读取

减少重复静态规则和无关历史，保留会影响操作的约束、占用及人类指令。工具使用字符预算，不猜测模型账单。

## 固定入口各读一次

安装项目先读 START_HERE，以及尚未加载的根 AGENTS 和 RULES。同一会话不重复全文导入；规则变更才重读相关部分。
WORKFLOW 只在执行具体步骤时查，README 只在字段不熟悉时查，故障手册通过索引定位相关条目。
套件源码使用根 AGENTS 的开发规则，不重复读发布用 RULES；本机 `.agents/` 运行记录不能加入静态入口。
上下文恢复先重查动态状态并核对自己的 ID、分支和文件范围，不能把上次摘要当现状。

## 动态摘要有预算

在目标项目根运行：

```text
python .multi-agent-collab/tools/agents_status.py --context --agent codex
python .multi-agent-collab/tools/agents_status.py --context --agent codex --session <自己的ID> --max-chars 6000
python .multi-agent-collab/tools/agents_status.py --context --agent codex --json
```

源码仓库将工具路径换成 `tools/`，继续使用 `.agents/` 本机记录；旧安装沿用原路径。
命令默认不访问网络、不缓存动态状态，提供实际策略、占用与待机摘要、定向未答 inbox 原文、近 1–2 天有限日志。
已登记会话的业务命令带自己的平台/ID，核验后顺带记录活动，无须单独反复 heartbeat；纯审计可加 --no-activity。
`--max-chars` 控制正文字符预算，JSON 元数据说明截断和未读项；它不等于 token 数。

- 返回 0 表示本次检查无告警；仍需写前的 fetch、PR、进程/reflog/mtime 和文件范围登记。
- 返回 1 时检查告警和未读列表。预算不足先按路径读取原文，必要时增加预算；不能凭部分指令 ack、回复或继续依赖它的工作。
- 返回 2 表示工具或数据有错误，先排查，不能当放行。未知归属、重复记录和损坏内容不应消失在摘要中。
- `--brief` 适合只需一行看板状态的场景，不替代定向指令与策略核查；完整看板和源码仅在需要时读取。

大量历史日志不是启动资料。日常只记阶段结果、下一步、阻塞和验证证据；不要把完整命令输出反复复制到入口、会话和日志。
上下文容量不足时保留当前任务、文件范围、分支/ID、未答指令、测试证据与下一步；历史详情保留路径，按需读取。

## 委派和长任务控制重复

独立子任务只传目标、相关路径、真实基线/会话 ID、接口约定和验收标准，不复制无关聊天与整本历史。
主会话登记完整范围，子代理只读写分配的文件，统一整合结果和执行 Git 操作。
共享同一任务会话时复用主会话本轮可核验的协调结果；独立对话或任务仍须重查动态状态，避免重复分析同一源码。
阶段更新记录新结论与下一步，不重复完整任务历史；测试已有有效证据且代码未再变化时，不为输出更多结果反复运行相同检查。
暂停、失败、截断和新指令仍需重新核对，不能用“省 token”跳过安全门禁。

## 可复现测量

在套件源码运行：

```text
python scripts/measure_context.py --baseline 2e8ba9e --encoding o200k_base
python scripts/measure_context.py --baseline 2e8ba9e --encoding o200k_base --json
```

字符和 UTF-8 字节数始终可得。`tiktoken` 及编码数据可选；缺少本地编码时只报告字符/字节，不自动安装或下载。
比较基线和当前同一组文件、同一编码；项目原有 AGENTS、实际会话内容和工具输出另外计算。

2026-11-04 的测量进程使用 tiktoken，在编码数据可读的环境中加载 `o200k_base` 并实际计数；数据当时只留在进程内，没有保存缓存。
当前离线脚本缺缓存时不会重新下载，也不能重算下列 token 快照，仍可独立复验字符与字节数。

| 静态文本 | 基线 tokens | 优化后 tokens |
|---|---:|---:|
| 发布 RULES | 5,347 | 2,285 |
| START_HERE | 1,004 | 552 |
| 安装后两份必读文档合计 | 6,351 | 2,837 |
| 套件源码 AGENTS | 5,420 | 1,827 |
| Claude 手动任务入口 | 709 | 237 |

该历史快照中两份必读文档减少 **55.3%**。这是指定编码的静态文本减少量；真实任务总 token 还包含项目规则、提示词、代码、工具结果和模型输出，实际比例需按客户端用量统计。
消息提示加入前，2026-11-07 的相同文本为 **12,203 → 5,075 字符（减少 58.4%）**，UTF-8 字节为 **21,744 → 10,455**。新增规则后的体积以当前测量为准，上表 token 数是历史编码快照。
字符预算与静态精简不会降低分支保护、占用检查、未读指令处理、真实测试或授权要求。

2026-11-08 最终冻结工作副本实测：RULES + START_HERE 为 **12,203 → 5,432 字符（减少 55.49%）**，
UTF-8 字节为 **21,744 → 11,178（减少 48.59%）**，6,500 字符预算通过。当前编码缓存缺失，`tokens=null`。

## 业务工具顺带发现消息

每个业务命令顺带读取本地通知，只有相关未读项或未处理人类事项才附加短提示。
状态查询、心跳、更新等入口复用已有工作区信息，不再启动第二个完整 status 进程，也不读取历史日志或联网查更新。
普通业务工具的提示只带数量和读取参数；正文按需读取。默认 read 只展开未读内容，同一会话显式标读后不重复普通正文。
显式完整 `--context` 仍按协调摘要口径展开未答事项原文；日常提示节省的是额外轮询与相同正文的重复读取。
已读人类事项仍须处理，但只有短提醒；没有新未读内容时不引导再次调用 read，JSON 的 `read_command` 为 `null`。

通知计数和消息列表计算完整内容版本后只保留元数据，避免同时暂存每条正文；完整 `read` 仍读取正文，预算截断不标读。
64 条各 64 KiB 消息的实际代码配对复测：峰值内存中位数 **9,498,515 → 1,246,245 字节（约减少 86.9%）**，
通知输出、版本和未读判断完全一致，文件字节/mtime 不变且没有 Git 调用。耗时差异很小，不据此宣称整体工具提速。

内容版本按实际字节核验，不能仅靠 mtime/大小缓存；同平台实例和不同 worktree 分开保存回执。
原始字节用于读取稳定性核验，通知游标按当前收件方向的内容版本去重；自己追加执行计划不让自己重读原要求，回复变化仍通知原提问者。
查消息、检查更新和预览都不顺带写“已提示”游标；仅完整显式标读才更新阅读回执，失败/截断不吞消息。
带明确身份的正常业务调用可节流写自身活动，活动记录与阅读回执独立；--no-activity 审计、预览和更新检查保持零写。
原确认版本只涵盖完整原要求和位置，正常进度回复不让任务重新确认；新要求变化则必须重新阅读。

2026-11-08 同进程、新旧算法配对测量（300 条长消息、6000 字符预算）：
上下文裁剪 CPU 中位数 **2.406250 → 0.203125 秒**，约减少 **91.6%**；输出字典完全一致，未读和截断告警保持。
这只衡量裁剪函数，当前机器负载会影响 wall time，不能据此承诺整个工具的速度或账单 token 降幅。
工具输出的真实字符与时间、完整回归及源码指纹保存在私有测试证据中；它们与模型账单分别报告。

初轮 102 条真实命令另有 30 组输出采样。按相同采样口径构造 10 轮：旧心跳加每轮完整 context 合计 **39,750 字符**，
首次短提示加一次完整 read 和后续心跳合计 **5,622 字符（减少 85.86%）**。这是实测长度的场景算术，未测模型账单。
最终代码另经 10 条已安装命令、39 项检查补测，已读 AI 心跳为 109 个 LF 归一字符（Windows 原始 115 字节），
已读 open 人类事项心跳为 254 个 LF 归一字符（原始 267 字节），JSON 的读取命令为 null，默认 read 不重复正文。
不同源路径和换行口径会影响输出长度，不能把这部分差异归因于代码提速或 token 费用变化。

## 活动与收尾提示的成本

普通业务调用同时带身份、记录活动和发现消息；长测试/构建可用 run，避免额外轮询和专门续活命令。
活动不输出重复进度正文，不保存完整命令参数；身份无法核验时不替别人续活。
最终答复前的收尾清单集中在 START_HERE，各平台只指向该清单；任务完成默认 finish --standby，未完成 handoff，新任务 activate 重新登记。
详细状态转换和命令只在 WORKFLOW 按需读取，不能为减少字符删掉指令门禁或真实测试要求。

2026-11-09 活动/待机最终工具冻结副本实测：RULES + START_HERE 为 **12,203 → 6,327 字符（减少 48.15%）**，
UTF-8 字节 **21,744 → 12,949**，6,500 字符预算通过；编码缓存缺失，`tokens=null`。
相比上一轮增加了命令归属、待机/激活、运行中门禁和答复前收尾清单，仍通过统一入口避免各平台重复整章规则。

活动更新成功不增加 CLI 输出，60 秒内重复调用不重写活动；阅读回执与任务确认保持独立。
运行中的提示按内容版本使用内存游标去重，不持久化“已提示”或假标读；同数量、同路径的新内容仍再次提示。
真实默认周期补测中普通消息只提示、原命令退出码保留，下一条命令仍须纳入新要求。
以上是文本体积与机制检查，不是模型用量或计费统计；历史内存/CPU/输出场景数据仍按各自日期记录。
