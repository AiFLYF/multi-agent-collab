# 原会话失联时如何接管

同一任务继续用自己的 ID；原执行者仍能回应时，优先让其 handoff / finish。
只有原会话失联、占用确实妨碍已授权任务时，才使用这里的流程。心跳过期本身不会释放占用。

## 先检查，再生成可核对的计划

```text
python tools/agents_session.py takeover-inspect <原会话ID> --json
python tools/agents_session.py takeover-plan <原会话ID> --agent <当前平台> --reason "接管理由" --json
```

inspect 只读。plan 在主 worktree 的 `.agents/takeovers/` 保存快照，并在 inbox 发布 agent 接管声明。
计划包含原 ID、所属工作区、分支与提交、文件范围、Git 状态以及改动文件的指纹，不复制文件内容。
它只申请收回协作占用，没有执行接管。

生成计划前必须交叉核对看板、进程、reflog 和文件修改时间。工具会拒绝以下情况：

- 原会话已结束、分支改变、心跳缺失或无效，或不同工作区有相同会话 ID。
- 心跳、会话记录或改动文件在 15 分钟内更新；原工作区存在 Git index.lock。
- 有待处理的人类指令，或已有待处理接管计划。
- 改动超过 100 个文件或 8 MiB，涉及链接、目录或子模块等需要人工核对的情况。

系统锁只约束本套件的登记工具，不能证明别的编辑器或进程已停。没有足够证据时继续只读调查。
无法使用自动流程时，保留现场与记录，让用户决定具体处理方式；不要直接删 session 或改成 done。

## 等待并确认具体计划

把 plan 返回的计划 ID、原会话、分支、提交和未提交改动交给用户核对。
取得用户对**该计划**的明确确认后，再使用以下命令；已有的明确确认无需重复索取。

```text
python tools/agents_session.py takeover-apply <计划ID> --agent <当前平台> --confirm-session <原会话ID> --approval-note "实际用户确认的记录" --json
```

从声明发布起至少等待 5 分钟，期间继续检查 inbox。任何回复、心跳、工作文件、暂存内容、分支/提交或策略变化，
都会使 apply 停止。不能为了通过校验修改快照、时间戳或删除回复；原计划取消后重新协调。
`--approval-note` 和 `--agent` 都只是记录与防误操作字段，不是身份认证，也不能代替用户实际授权。
`--ack-inbox` 仅表示真实阅读并纳入任务，不能绕过暂停、取消、避让要求。

成功后原会话保留全文并置为 `closed`，记录执行者、原因与计划 ID，同时回执关联交接并追加日志。
这不表示原任务完成或测试通过。Git 分支、提交、stash、暂存和工作文件保持原状。

后续先确认原工作区不再有写入进程，保存和核对未提交文件，再从计划里的原提交建立自己的任务分支并登记。
新 worktree 不会自动带走未提交内容，禁止未经核对就清理旧工作区。后续汇报必须注明继承的提交和文件。

## 取消或处理中断

```text
python tools/agents_session.py takeover-cancel <计划ID> --agent <发起平台> --reason "取消原因" --json
```

取消会保留计划、声明及所有回复，只改自己的计划状态，不释放原会话占用。
已应用、已取消或正在应用的计划不能重复执行。
多份本地记录无法同时原子写入；工具在变更会话前先记 `applying` 审计状态。
若写入中断，应逐项核对计划、原 session、交接条和 worklog 后人工恢复，不能重跑命令赌结果。

接管记录属于本机数据，即使 `uninstall --purge-files` 也会保留；卸载会移除忽略规则，避免将残留记录误提交。
