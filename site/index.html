01WHAT它是什么

AI 各干各的， 规矩只有一套。

分别启动你正在使用的 AI 工具，再把它们接入同一个项目。 通过规则入口、会话登记和本地消息，每个会话知道谁在做什么、哪些文件已占用、接下来该读什么。

PILLAR 01

一份规则总章

保留项目原有 AGENTS.md / CLAUDE.md，用简短入口连接独立的 .multi-agent-collab/RULES.md。平台按需安装，开工、测试和人类指令遵守同一套协作规则。

PILLAR 02

一块共享黑板

.multi-agent-collab/ 就是本机共享记忆：谁在哪个分支干什么、心跳还活不活、有问题问谁、前任走了怎么接手。全是几个 Markdown 小文件，不进 git，切分支不丢。

PILLAR 03

一组协作命令

agents_session.py 登记会话、检查文件占用、更新心跳并收尾；agents_status.py 提供摘要和网页指挥台。两者都只需 Python 标准库。

03SOP四条交规

四条交规， 写在 AGENTS.md 里。

RULE 01 · 文件纪律

先声明范围，再修改文件

开始任务用 agents_session.py start 登记 --files。文件与目录重叠时先协调，扩大范围先检查；状态按会话保存，worklog 只追加。

RULE 02 · 判活方式

心跳判活，系统锁保护登记

系统锁仅串行保护状态更新，进程退出会自动释放。心跳超过 15 分钟算失活，文件占用仍保留；接管计划需等待与确认，快照变化就停止，保留原提交和工作文件。

RULE 03 · 交叉验证

看板上没人 ≠ 真的没人

忘了注册会话的 AI 是隐形的。除看板外，还要交叉看 git reflog、文件 mtime、有没有构建进程在跑——三个信号都对上才下手。

RULE 04 · 数据边界

协作文件只留本机，不进 git

独立目录默认写进 .gitignore：本机记录切分支不丢；共享入口已有的 Git 跟踪状态保持不变。代价是没有云端备份——重要节点把 .multi-agent-collab/ 拷到仓库外即可。

2 分钟前 5 分钟前 11 分钟前 14 分钟前 > 15 分钟

最近更新一眼可见：青色点表示心跳正常，红色点表示需要核查。 长任务前写明预计返回时间，并在阶段间隙更新心跳；失活和 blocked 都保留占用，接管仍需检查、等待与用户确认。

04TOWER你的指挥台

AI 看文件， 你看网页。

  • 01每 5 秒自动刷新。每个 AI 一张卡片：哪个平台、在哪个分支、做什么任务、几分钟前还有心跳（绿 = 正常，红 = 失联）。
  • 02问题与交接一眼可见。未答复的 inbox 留言、前任留下的「下一步 / 阻塞点」，不用去翻文件。
  • 03worktree 告警。有 AI 在没登记过的目录里动了手脚，红色告警直接拍在页面上。
  • 04留言、计划、结果分别可见。从看板发送到 inbox；会话、检查、状态或更新工具顺带提示相关新消息。AI 读取后回复计划，处理完再回复结果并更新事项状态。
  • 05三档安全。默认只听本机；局域网可以只读大屏，或设密码后可指挥——「对外可写又无密码」的组合会被拒绝启动。
01 / 发送

写入本机 inbox

选择会话或广播，普通留言与暂停、取消、避让使用各自的类型。

02 / 提示

工具返回短通知

调用套件业务工具时发现相关新消息，再按提示读取正文。

03 / 处理

先阅读，再回复计划

标读仅表示读过；普通事项仍保持 open，控制要求立即处理。

04 / 结果

原消息回复并收尾

完成普通事项后写结果并 answered；控制只有人类明确解除才可恢复。

消息在下次套件工具调用或主动检查时送达。长命令中途和空闲时需按协作流程检查；本套件不会自动启动 AI，也不会把命令注入任意终端。在演示中体验完整过程 →

5. 新安装把套件规则、工具、记录放入 .multi-agent-collab/，默认在项目 .gitignore 的标记区忽略该目录；平台入口按精确路径写入 .git/info/exclude。已有 AGENTS.md 等共享入口保留原文，只维护小段标记。已跟踪入口的差异正常显示，不取消跟踪，不隐藏索引改动。来源不明的独立目录、损坏标记或被修改的套件文件先报告并保留现场。
